## 改动一：新增 `list_chat_messages` 工具（核心）

**新文件** `core/tools/chat_history_tool.py`（290 行）

按「日期 + 小时区间」穷举读取原始聊天记录，不依赖相似度命中，从结构上保证「不会漏」。

- 类：`ChatHistoryTool(FunctionTool[AstrAgentContext])`，name = `list_chat_messages`
- 参数：`date`（默认空=今天）、`start_hour`（0）、`end_hour`（24）、`limit`（300，上限 1000）、`include_room_state`（false）
- 数据源：`conversations.db` 的 `messages` 表（原始逐条记录，不受上下文裁剪和记忆摘要影响）
- 清洗：
  - `_ROOM_STATE_RE = re.compile(r"[（(]房间实时状态[^）)]*[）)]")` —— 剥掉每条都带的房间状态尾巴（实测 400/400 条都有）
  - `_MSG_ID_RE = re.compile(r"\[MSG_ID:-?\d+\]")` —— 剥掉 MSG_ID 标记
  - 剥完为空 → 标成「[发送了图片或表情]」，不编内容
  - 单条超 800 字截断
- 称谓：assistant 的纯数字 `sender_name`（QQ 号）显示成「我」，user 空名显示成「对方」
- 返回：`{date, range, session_id, count, truncated, messages:[{time, speaker, role, text}]}`

**一个踩坑修正（重要）**：第一版照抄 recall 工具用 `resolve_memory_scope()` 取会话 ID，是错的。线上 `memory_scope_mode = "global"` 时它返回伪作用域 `livingmemory:global`，拿去查 conversations.db **永远 0 条**，等于工具完全失效。改成 `session_id = event.unified_msg_origin`（cron 事件里这个值就是 `大肥鱼:FriendMessage:<owner-qq>`，与库里的 session_id 完全一致）。

## 改动二：`storage/conversation_store_messages.py` 补按时间区间查询

第 883 行起新增：

```python
async def get_messages_by_timerange(
    self,
    session_id: str,
    start_ts: float,
    end_ts: float,
    limit: int = 300,
) -> list[Message]:
```

SQL：`WHERE session_id = ? AND timestamp >= ? AND timestamp < ? ORDER BY timestamp ASC, id ASC LIMIT ?`（左闭右开）

原有的 `get_messages_range()` 是按 OFFSET/LIMIT 切片，没法按时间过滤 —— 这就是要补的空缺。`messages` 表已有 `idx_msg_session ON messages(session_id, timestamp DESC)`，按时间区查不会慢。

## 生效方式

**note 改动立即生效**（`_run_job()` 每次执行都从库重读），下一次 23:00 就用新 note。

**新工具需要重载插件**：工具注册发生在插件加载时（`_ensure_runtime_components()` → `_register_agent_tools_if_needed()`）。在 AstrBot 面板里重载 `astrbot_plugin_livingmemory` 即可，不必重启整个 AstrBot。

重载后怎么验证工具注册上了：
1. 面板插件日志里搜 `ChatHistoryTool`，或搜不到就说明没注册。
2. 更直接：在聊天里问大肥鱼「你现在有哪些工具」，或让她试一次「把今天 8 点到 12 点的聊天记录拉出来」。
3. 也可以看日志里 LLM 请求的 tools 列表是否含 `list_chat_messages`。

**回滚方式**（如果出问题）：

## 已知取舍

- 工具每次最多返回 300 条（`limit` 上限 1000）；11-19 全天 242 条，正常不会触发截断，但极端活跃日可能被截断，此时返回值里 `truncated=true`，note 里要求分段拉取正是为了规避这点。
- `include_room_state` 默认 false（剥掉房间状态）。这是按「只看真正说的话」的要求定的；万一以后想还原，把它设 true 即可。
- recall 参数（`top_k=5`、`max_k=10`、`recent_memory_count=2`、`enable_agentic_recall_beta=false`）**全部没动**，按你的要求。
