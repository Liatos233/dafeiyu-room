# 交接文档：角色与家具「穿模」问题（全过程 + 现方案）

> 交接对象：下一个接手这个问题的模型/人。
> 这份文档只讲**穿模这一条线**：踩过哪些坑、每次为什么失败、现在的架构是什么、怎么验收。
> 系统总览见 [`HANDOVER.md`](./HANDOVER.md)；家具/平台模块速查见 [`HANDOVER-room-seats.md`](./HANDOVER-room-seats.md)。

- 仓库：`<repo>`
- 线上：`http://<your-server-ip>:3100/room/`（当前部署 `5ced7f8`）
- 本文最后更新：2026-11-15，对应本地 HEAD `5ced7f8` 之后的文档提交

## 1. 问题的本质

角色是 **2D 立绘（billboard 平面）**，房间是 **3D 网格**。所以「穿模」实际有两类，修法完全不同：

| 类型 | 判定依据 | 典型表现 | 修法 |
|---|---|---|---|
| **A. 几何相交** | 占用网格 `hits > 0`：身体柱与实体在高度区间内相交 | 陷进床里、腿插进坐垫、头顶穿伞面 | 改坐标/高度/落点 |
| **B. 遮挡错觉** | `hits = 0`，但家具近侧栏杆在相机前面挡住她的小腿 | 看着像「人在椅子里面」 | 深度偏置或换位（改不了几何） |

**排查第一步永远是分清 A/B**，否则会一直「修了没用」。

## 2. 时间线：踩过的坑与失败原因

### 阶段一：只调坐标（失败）

最初座位点是手写的，直接落在家具几何里：

| 家具 | 旧座位点 | 问题 |
|---|---|---|
| 沙发 | `[6.3, 5.12]` | 正好在「坐垫/靠背交界」，立绘贴进靠背 |
| 床 | `[11.4, 1.32]`，床面高度写死 0.54 | 实际被子顶 **0.644**，人陷进去 10cm |
| 沙滩躺椅 | `[12.30, 10.58]` | 抬起的靠背在 x≈12.14，身体柱压到 |
| 阳台躺椅 | `[3.0, 8.4]` | 靠背在 x≈2.4，勉强 |

**为什么失败**：只改坐标不改高度来源，家具稍微一改（床品、坐垫）就再次错位。

### 阶段二：坐标 + 两段式上座 → 解决「斜着穿过去」

原来 `seatLerp` 让水平位移和抬升同时进行，t=0.5 时人已经在坐垫里、高度只有一半。

改成两段（`RISE = 0.55`）：

```
上座：0~55% 原地抬到座面高度 → 55%~100% 横移进座面
下座：0~55% 横移退出 → 55%~100% 落地
```

### 阶段三：发现「缓动滞后」

服务端高度已经在涨，客户端 `actor._elev` 用 `dt*4.5` 缓动追，位置又用 `k*1.4` 缓动 —— 上座 620ms 里视觉高度落后约 0.2s，人已经横移进去、高度还没上来。

修法：

- 服务端 `homeView().her.transitioning = !!(mounting || dismounting)`
- 客户端在 `transitioning` 期间 `snap: true`（位置/高度直接吸附，不缓动）
- 过渡结束后 **300ms 内**同样不套用几何修正

### 阶段四：几何驱动（真正的解法）

写死常量换掉，改成向场景几何提问（`world.js`）：

```js
world.surfaceYAt(x, z)        // 多点向下射线，取最高表面（垫缝/被褶都覆盖）
world.blockedAt(x, z, r, footY, height)  // 身体柱是否与实体相交
world.bestSeatPoint(x, z, expectedY)     // 座面范围内找「同表面 + 不撞」的落点
```

配套修正：

- 座面高度 = 真实表面 **+1.2cm**（`SEAT_EPS`，脚底不再压进坐垫）
- 躺姿也贴合真实床面（`a072e11`）
- 床面抬升 `BED_RAISE` 只在**休息态**（asleep/sleep/nap）叠加，否则起身瞬间会「掉下来」（`902922d`、`283715e`）

### 阶段五：性能翻车 —— 每帧上万次射线

上面那套几何查询最初是**每帧**跑的：

```
bestSeatPoint 最多 ~400 个候选 × blockedAt 每次 134 条射线 ≈ 5 万次 raycast/帧
```

表现就是「页面巨卡、浏览器崩溃」。

修法（`5b8dc2c`）：改成**一次性预计算的 0.1m 占用网格**：

- `buildOccupancy()`：世界构建完遍历网格 AABB 填 `cellTop / cellLow / cellSolid`
- `surfaceYAt` 0.15µs、`blockedAt` 0.40µs（1000 次调用实测）
- 落点解按 `房间:座位:坐标` **缓存**，位置不变不重算

### 阶段六：把「能站的家具」从 K 区拆出来

原来沙发/床/躺椅和墙一样都写在 `NAV_KEEPOUT` 里，语义混乱（K 区本应是「不能进」）。

改成两层（`de6466b`）：

| 概念 | 数据 | 作用 |
|---|---|---|
| K 区（障碍） | `NAV_KEEPOUT` → 导出 `HOME_KEEPOUT` | 墙/水面/栏杆，永远不能穿 |
| 可站立平台 | `HOME_PLATFORMS`（从 `spots.support` 派生） | 地面高度进不去，只能从攀爬点抬升进入 |
| 寻路用 | `NAV_BLOCKS = KEEPOUT + 平台地面投影` | 两者都挡路线 |

### 阶段七：平台挡不住路线（关键 bug）

拆完 K 区后发现：**路线仍然会横穿沙发**。实测 `route inside sofa rect: 11 次 → [5.36, 4.79]`。

根因：寻路里有一句「端点落在障碍矩形内就豁免」，本来是给「从座位上离场」用的，但它对所有矩形一刀切，平台因此被整段穿过。

修法（`e42b60b`）：豁免收紧成**只允许该平台自己的座位点**：

```js
function endpointAllowedInRect(pt, rect) {
  const seat = platformSeats().find(s => s.rect === rect);
  return seat && distance(pt, seat.pos) <= 0.12;
}
```

同时：

- `bal_w` 节点原本在阳台躺椅矩形内 → 移出 → 后来整体合并到 `bal_chair`（`5ced7f8`，节点 69→68）
- 阳台躺椅上座点改为 `bal_chair` 位置 `[3.58, 8.3]`

### 阶段八：动画被掐断（附带问题）

现象：一个动作刚开始播就被下一个片段替换。

原因：`clipFor()` 每帧重新决策，坐姿兜底又无差别覆盖所有 kind。

修法：

- 片段**最短保持 350ms**（走路/睡眠类紧急片段不受限）
- 坐姿兜底只在 `kind ∈ {idle, free, sit}` 生效
- 冒烟脚本统计 `quickCuts`（900ms 内连续切换次数）

### 阶段九：坐姿素材的现实

素材库里**没有「坐在任意家具上」的循环帧**：

- `沙发打瞌睡`：画面自带一把扶手椅，用了会两把椅子叠一起
- `dance`：站姿，站在坐垫上
- `nap`：躺姿，只适合床

所以目前坐姿兜底用 `dance`，**站位是站着的**——用户已明确「站着可以，但不能穿模」，所以这是可接受状态；根治需要补一个坐姿 webm。

### 阶段十：遮挡错觉

修完几何后用户仍觉得「穿」，逐帧截图发现：`hits = 0`，是家具近侧栏杆在相机前面遮挡。

修法：站立家具上时朝相机方向**前移 0.22m** 做深度偏置（`21d3ac2`）。这是视觉补丁，不是几何修正；换视角仍可能露馅。

### 阶段十一：其他道具

- 遮阳伞整体抬高 0.4m（边缘 1.56 → 1.96），否则站上沙滩躺椅头顶穿伞面
- 落地灯禁走区随灯位更新为 `[4.73, 4.98, 5.17, 5.42]`
- 饮水机旋转 -90°、灶台/水杯架/水果盘/盒子做成命名单元（编辑器用）

## 3. 当前方案（一张图）

```
服务端 src/home-state.js
  HOME_LAYOUT.spots ──┬─ support/mount/pose（座位定义）
  SURFACES ───────────┘
  HOME_PLATFORMS      ← 从 spots.support>0 派生：{rect, top, climb}
  NAV_KEEPOUT         ← 纯障碍
  NAV_BLOCKS          ← KEEPOUT + 平台投影（寻路段全部用它）
  endpointAllowedInRect ← 平台内只允许座位点做端点
  seatLerp            ← 两段式升降/横移
  homeView().her.transitioning ← 客户端据此关闭缓动

客户端 public/room
  world.buildOccupancy() → 0.1m 网格（cellTop/cellLow/cellSolid）
  world.surfaceYAt / blockedAt / bestSeatPoint / nearestClearSpot
  app.js:
    - 落点解缓存 seatSolveKey/seatSolve
    - transitioning / 过渡后 300ms 不做几何修正
    - 高度 = clamp(serverElev, surface+0.012, surface+0.06)
    - 深度偏置 0.22m（仅站立家具上）
    - 片段最短保持 350ms
```

### 不变量（改动时别破坏）

1. 平台矩形在**地面高度**不可进入（`NAV_BLOCKS` 参与所有寻路段判断）
2. 平台内只允许「该平台座位点」作为路径端点（其余一律判穿）
3. 进出只走 `climb` 点；先抬升后横移，下座反向
4. 过渡期与结束后 300ms 内，客户端不套用落点解/不重新采样高度
5. 每帧不做重几何查询（`bestSeatPoint` 必须走缓存）
6. 改 `home-state.js` 后必须跑 `node scripts/gen_nav_data.mjs` 重新生成客户端导航数据

## 4. 验收工具与指标

| 脚本 | 作用 |
|---|---|
| `scripts/smoke-path.mjs` | **主验收**：驱动角色走 10 段路径（走动/四个家具上下座/点沙发内部地面），每 250ms 采样 `window.__drawState`，用网格判定穿模，输出 `report.json` + 截图 |
| `scripts/seat-check.mjs` | 同页内依次去四个座位抓图（按高度等待，不会拍到半途） |
| `scripts/capture-mount.mjs` | 上座过程逐帧抓图（自定义相机，避免被主循环覆盖） |
| `scripts/render-view.mjs` | 指定相机渲染单帧 |
| `scripts/page-eval.mjs` | 页面内执行 JS 取结果（调试主力） |
| 服务器 `/root/route_check.py`（临时脚本） | 横穿测试：从 A 到 B 采样 route，检查是否进入平台矩形 |

### 最近一次结果

```
smoke：440 帧，10 段，hits 全为 0
      maxStillJump 0.22m，clipSwitches 21，quickCuts 1
route 横穿：sofa / bed / chair 三组，进入平台采样 0
查询成本：surfaceYAt 0.15µs，blockedAt 0.40µs
```

- `hits > 0` → 几何相交（真穿模）

## 4.5 重要回归（2026-11-15 下午，务必知道）

**占用网格曾经根本没建起来**：`world.buildOccupancy` 的调用写在函数定义之前，
异常被 `try/catch` 吞掉，`surfaceYAt` 全返回 0；后来修了顺序又因为在
`mergeStaticDecor` 之后建，整屋被合批成一个大 AABB，高度全变成天花板顶 2.85m。

后果：**那段时间冒烟测试的「0 hits」是假象**（网格空 → 永不判定相交）。

现在的修复（`697b584` / `4ce37a8` / `5496dbf` / `3a1ef67`）：

- 网格在 `buildOccupancy` 定义之后、`mergeStaticDecor` 之前构建
- 跳过天花板；新增「1.3m 以下表面」表 `cellTopLow`，伞面/吊灯不再被当成可站立面
- 网格按 AABB 栅格化对**斜放的躺椅**会过覆盖 → 座面落点改用精确射线 `world.preciseBlocked`
- 冒烟脚本判定也改用 `preciseBlocked`（`scripts/smoke-path.mjs`）

修好后冒烟首次报出真实相交（bed/lounger 各 10+ 次），随后修掉：

- 绘制高度**永不低于所在位置的真实表面**（含过渡期），避免服务端 elev 还是 0 时被画进家具
- 「目标点落在平台内」的守卫改为逐步外推，直到不再与任何区块相交
- 沙发座位点原来正好压在两块坐垫的**接缝**上（x=6.3），腿会落进缝里 → 移到左坐垫中心 `[5.84, 4.95]`，客户端 `SOFA_POINT` 同步
- 深度偏置 0.22→0.42，但改为**碰撞回退**：偏置后若撞到实体就逐档减小（之前会把人推进靠背，取决于相机方位）

最新验收（精确射线判定）：**176 帧全部 0 相交**，`maxStillJump 0.06`，`quickCuts 3`。
部署：`965befe`。

## 4.6 简化重构（2026-11-15 傍晚，当前架构）

用户反馈「各种屎山、走着走着消失闪现、卡」，于是把客户端几何修正层**整层删掉**：

**现状（唯一模型）**

```
服务端：座位 = rect(禁走) + top(座面高) + mount(唯一入口)
        上座 = 原地从 0 升到 top（55% 时间）→ 沿座面平移到座位点
        下座 = 先平移回 mount → 再降到 0
        过渡期间 pos 与 elev 同源插值（seatLerp）并随快照下发
客户端：只按服务端 pos/elev 画，不做任何采样/搜索/偏置
        过渡期 snap（不做缓动）+ 禁止路径外推
        站上平台时高度下限 = 平台 top（防止快照延迟导致沉入）
        精灵 frustumCulled = false（修「走着走着消失」）
```

**这次修掉的真 bug**

1. `homeView` 的 `elev` 用的是 `s.elev`（只在过渡结束才赋值），而 `pos` 用插值 →
   过渡时位置已经到座面、高度还是 0 → 「贴着地滑进家具，最后突然弹上去」
2. 上座完成后 `setActivity(..., t.elev, ...)` 把高度重置成布局里的 elev（沙发是 0）→ 坐下瞬间掉回地面
3. 客户端 `walkPredict` 在过渡期继续外推 → 预测位置滑进家具
4. `SURFACES.bed_top` 写 0.54，实际床垫面 0.65 → 一直陷 11cm

**已删除的代码**（不要再加回来）

- `bestSeatPoint` / `nearestClearSpot` 的运行时调用
- 深度偏置（0.42 → 已删）
- `preciseBlocked` / `quickBlocked` / `nearMeshes` 的运行时调用（保留函数仅供离线测试）
- 每帧 `surfaceYAt`

**验收**：冒烟 442 帧，`maxStillJump 0`（无瞬移），各阶段 hits 0–3（贴边采样残差），
床/沙发/躺椅截图见 `ref-sheet.png`。

## 5. 已知残留（未彻底解决）

1. **立绘平面被近侧家具遮挡**：`hits=0` 仍可能「看着穿」。已加 0.22m 深度偏置；根治要坐姿素材或接受站边上。
2. **窄座椅**：阳台/沙滩躺椅座垫约 0.9–1.0m，立绘视觉宽度约 0.9m，站上去边缘必然悬空。
3. **没有坐姿循环动画**：坐姿兜底是 `dance`（站姿）。
4. **平台数据双源**：`home-state.js` 是事实源，`nav-data.js` 由 `gen_nav_data.mjs` 生成，手改会被覆盖。
5. **深度偏置是相机相关的**，切换视角可能露馅。

## 6. 排查手册（下次遇到「又穿了」）

1. **先跑冒烟**：`node scripts/smoke-path.mjs <输出目录>`，看 `hits`
2. `hits > 0`：
   - 看 `report.json` 里出问题的阶段与坐标
   - 用 `page-eval` 打印 `window.__drawState`（pos/elev/pose/spot/clip）
   - 调 `world.surfaceYAt(x,z)` 与 `world.blockedAt(x,z,0.24,elev+0.03,1.35)` 看是谁挡住
3. `hits = 0` 但仍「看着穿」：这是遮挡（B 类），用 `seat-check.mjs` / `capture-mount.mjs` 出图确认，不要再去改坐标
4. 路线问题：用服务器 `route_check.py` 或直接采样 `her.route`，检查是否有点落在平台 rect 内
5. 动画问题：看 `quickCuts`，再看 `clipFor()` 是否被兜底规则抢了

## 8. 下一步建议（按优先级）
