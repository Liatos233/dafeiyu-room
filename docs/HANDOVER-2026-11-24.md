## 0. 三十秒看完

一个中文虚拟形象「大肥鱼 / 小蓝鱼」的**单页 3D 房间 + QQ 机器人**系统。
你打开网页能看到一间 13.2×9.0 米的大平层（含泳池露台、菜园），一个角色在里面走动、

3. **B 站自主活动**（`bili_whale` 插件，看视频、评论、回复）

## 3. 房间状态机（最容易改坏的地方）

### 3.1 单向数据流

```
浏览器  --POST /api/home/act-->  bridge  --applyHomeAction-->  home-state.js
   ^                                                                    |
   +------------- GET /api/home/state（轮询，250~1200ms）<---------------+
```

**服务端没有后台定时器**。状态只在客户端请求进来时推进。所以：
- 轮询间隔直接决定"她到站"多久被发现
- 走路/上下座期间轮询降到 250ms，站着不动回到 1200ms

### 3.2 动作表

```js
HOME_ACTIONS = ['visit','pet','poke','feed','water','play','talk','sleep','wake',
                'lamp','command','go','place','sick','heal','clip','say']
```

### 3.3 `resetMotion(s, opts)` —— 所有动作都必须先调它

历史教训（**这类 bug 反复出现过三次**）：点动作面板时如果不清理旧的
`freeTarget / route / dismounting / mounting / dwell / walking`，
角色会"来回奔波"或"闪现"。

`resetMotion` 做三件事：
1. 清掉所有运动中间态
2. 重置 `pose` / `elev`
3. 重设 `nextDecisionAt` / `reactionUntil`

**但它必须保留"真的坐在家具上"时的高度**：先算 `spotOf(room, spot).support` 得 `seatY`，
若 `seatY > 0.05` 且当前 `pose` 是 sit/lie（或 elev 已抬起）→ 保留 pose 与 elev；
否则才 `pose='stand'; elev=0`。

> 我第一版忘了这条，导致身体先瞬移到地面再被插值拉回去——
> **单帧跳 0.480 米**，被 `test-motion` 的「渲染高度必须取 motionAt 的平滑值」抓住。
> 改这块一定要跑 `node scripts/test-motion.mjs`。

### 3.4 上下座的坑

- `arrive()` 创建 `mounting` 时必须记 `fromElev = 当前 elev`，**不能写 0**
  （否则 0.65 → 0.00 → 0.65 三帧跳变 = 家具上鬼畜）
- `advanceHomeState()` 里 `if (state.dismounting) return` 要**放在**
  `if (state.route || state.dwell)` **前面**。否则下座期间两者都是 null，
  会掉进 `decideTarget → beginRoute`，角色原地重新规划路线
- `beginRoute` 的 dismount 分支**不要**把 `spot` 改成 `'free'`（还在家具上）

## 4. 动作插值（`public/room/motion.js`）

**这是前后端共用的唯一实现**，`src/home-state.js` 和 `public/room/app.js` 都 import 它。
不要在前端另写一套插值——`test-project` 里有一条测试专门守着这件事。

```
motionAt(motion, now, fallbackPos) → { pos, elev, walking, done }
kind: 'still' | 'walk' | 'mount' | 'dismount'
```

`mount` / `dismount` 是两段插值（`seatAt(seg, now)`），常量 `RISE = 0.55` 是抬起段的时长。
支持 `fromElev` 指定起始高度。

## 5. 关于"鬼畜/抖动"这一类 bug 的通用排查法

判断链（在 `app.js`）：

```js
onFurniture = !walkingNow && (bubbleAnchorElev > 0.05 || her.pose === 'sit' || seatOverride)
snap        = SHOT || seatOverride || onFurniture
```

`snap === true` 时**每帧硬拷贝位置**。所以只要服务端状态和插值结果有一帧不一致，
就会看到剧烈抖动。

**排查步骤**：
1. 先确认服务端那一帧的 `pose` / `elev` / `kind` 是不是自相矛盾
   （比如 `elev 0.49` 但 `kind === 'walk'`，或 `pose === 'sit'` 但 `elev === 0`）
2. 再确认客户端是不是因为 `onFurniture` 被错误置真而 snap
3. `scripts/test-home.mjs` 里有一条「全动作残留检查」：17 个动作 × 2 种起始状态，
   断言不存在 `elev>0.05 && kind==='walk'`、也不存在 `pose==='sit' && kind==='walk'`。
   **加新动作就往这个矩阵里加一列。**

## 8. 已经修好的一批坑（别再踩一遍）

这一节是整份文档**最有价值**的部分。每条都是真实发生过、修好了、有验证的。

### 8.1 动作面板连点 → 角色奔波 / 闪现
四个 bug 叠在一起：
1. `command` 分支没清 `freeTarget` / `route` / `dismounting`
2. `freeTarget` 判断没检查 `command` 是否还在生效
3. `advanceHomeState` 只查 `route` / `dwell`，下座期间两者皆 null → 掉进 `decideTarget`
4. `beginRoute` 无条件 `state.spot = target.spot`，人还在家具上就改了落点

修法：抽出 `resetMotion()`，四个动作分支统一调用。提交 `9cc070f` / `f7a8920`。

### 8.2 B 站「额度暂时没有了」
根因：`traffic.mjs` 的 `readDay` 在**每次** `guarded()` 调用都自增（不管有没有命中缓存），
而轮询是 `check_every_min=1`（1440 次/天），`read_daily` 只有 3000 → 半天就烧穿。
修法：`check_every_min=10`、`read_daily=6000`、`read_hourly=400`，并重置当天计数器。
**不是模型额度问题。**

### 8.3 `bili_reply_comment` 发不出去（exit code 2）
三个缺陷：
1. `oid` 必需，但模型手里只有 BV 号
2. `--go` 被 append 了两次
3. 没有 `bvid` 参数，导致 `--bvid` 从来没被加上

修法：加可选 `bvid`、BV→aid 自动查、显式报 rpid 缺失、去掉重复 `--go`。提交 `481c3a0`。

### 8.4 主动消息人称错误（「游戏还打着没啊，手柄都没放下吧」）
根因：房间状态注入的是第三人称「她在客厅·沙发上，抱着手柄打游戏」，
模型把「她」当成了用户。
修法：在 `proactive_chat/core/services/context_service.py` 的最终 prompt 末尾
追加人称规则。**注意措辞**——第一版写过头（禁止问主人在做什么），
被用户纠正为「可以问主人的事，也可以说自己的事，但人称要对」。提交 `d224108` / `0cafe2f`。

### 8.5 句号偶发 + 禁句号后不再分段（连环两个 bug）
- 2087 条已发记录里只有 17 条带「。」（0.8%），几乎都在
  「句子 + 空格 + 下一句」的接缝处。persona 里那条「不用句号。」自己就带着句号，
  且挤在一堆 bullet 里权重被稀释 → 拆成独立 bullet、规则文本本身不带句号。
- **我修完之后引入了新问题**：禁了句号又没换行，切句正则
  `SENTENCE_RE = [^。！？!?；;…~\n]+[...]*` 只认终止标点和换行，
  整段成了一片 → 不再分段发。修法双保险：persona 要求「每说完一句话按一次回车」，
  `split_text` 加空格/U+3000 兜底（每片 ≥4 字）。提交 `17fe081` / `f4c28f7`。

### 8.6 窗外只有纯色，看不到海
**不是没画**——`skyTexture()` 里海、海平线、浪、远山、云、极光都画了。
问题是：等距柱状贴图里 **v=0 是北极、v=1 是南极，贴图 y=0.5 才是地平线**。
原来海画在 y∈[0.62, 1.0]、远山 y≈0.63 —— 全在**下半球**，被地板和房子挡死了。
修法：引入 `HORIZON = 0.505`，海放 `[0.505, 0.86]`，远山基座 `mtnBase = hgt*HORIZON`。
提交 `19529a7`。

> **判断等距柱状贴图的坐标，先背这条**：y=0.5 是地平线，y>0.5 在地平线**以下**。

### 8.7 床垫 / 被子偏移
三层没对齐：被芯 z=1.62（跨度 0.895–2.345）、床垫 z=1.30（0.325–2.275）、
床架 z=1.25（0.175–2.325）。结果被子滑出去、搭边悬空 2cm。

### 8.8 发 JPG 换画说「不支持的图片格式」（最新修好）
现象：用户在 QQ 发图让她换走廊的画，她说格式不支持。
日志实锤：**两次调用**，第一次 `image_base64` 是**文件路径**
（`/root/data/temp/media_image_*.jpg`），第二次是正常的 `data:image/jpeg;base64,...`，
第二次是成功的。图本身完全正常（`ffd8ffe1`，709KB）。

根因：AstrBot 把 QQ 图落到临时文件，模型看到路径就塞进 `image_base64`。
工具当时只认 base64 / data URL / http 直链，路径被原样 POST 给 bridge，
base64 解码成垃圾字节、mime 为空 → 「格式未知」。

修法（三处）：
1. 识别本地文件路径 → 读文件、按扩展名定 mime、转 base64
2. mime 认不出时按 **magic bytes** 兜底（`FFD8FF`=JPEG / `89504E47`=PNG /
   `GIF8`=GIF / `RIFF..WEBP`）
3. 参数说明写清「可以直接给本地文件路径」

**第四处是我第一版补丁自己引入的 bug**：判断路径用了 `"/" in b64`，
而 base64 字符集本身就含 `/`，于是对 940KB 字符串调 `os.path.exists()`
→ `ENAMETOOLONG` → 裸 base64 反而坏了。改成先卡 `len(b64) <= 400`。

服务器实测四种输入：
```
真实 JPG 路径        ✓
无扩展名文件（magic） ✓
裸 base64 无 mime    ✓
不存在的路径         ✗ 干净报错不崩
```
落盘文件与原图 **md5 完全一致**（`edc89b7e…`，709803 字节）。
补丁：`deploy/patches/room-link-gallery-path.sh` + `room-link-gallery-b64.sh`，提交 `f0d33ef`。

| 「76 个 Mesh 只有 8 个 castShadow，90% 家具不投影」 | `addMesh()` **默认就设** `castShadow=true` + `receiveShadow=true`，box/cyl 全走它 |
| 「没有踢脚线」 | `buildShell` 里有 `skirt()`，6 条 |
| 「没有门套」 | 有 `addDoorFrame()`，三面框 |

还有两次同类错误：
- 「全屋都没有窗帘」→ **卧室本来就有**（两大片 + 黄铜杆）。我 `grep curtain` 搜不到，
  因为变量名叫 `cur`
- 「书架缺失」→ **本来就有**（4 层 × 6 本 + 陶罐）。用户说「简陋」是对的，我说「缺失」是错的

**规矩**：
1. 说"没有 X"之前，必须**读那个函数的默认值**，不能只数关键字
2. 变量名可能缩写（`cur` / `bx` / `p`），grep 全名会漏
3. 不确定就写"未验证"，不要写成结论

## 11. 沙箱与命令的坑（不避开会浪费大量时间）

1. **不要用管道**：`| cat`、`node ... | Select-String` 这类会触发
   `ResourceUnavailable ... \\.\pipe\LOCAL\dotnet_... is denied`。
   → 改成先把输出写文件，再 `Select-Object -Last N`，或用 `Out-String`
2. **SSH / scp 需要 `danger-full-access`**（私钥在工作区外）
3. **命令里带中文 + 引号容易翻车**：用 PowerShell here-string 写脚本 →
   `$norm = $script -replace "\`r\`n","\`n"` → base64 → `ssh "echo $b64 | base64 -d > /tmp/x.sh && bash /tmp/x.sh"`
4. **`test-all.mjs` 返回 0/4 是沙箱问题不是代码问题**，单独跑各套件

## 16. 给新 AI 的三句话

1. **说"没有 X"之前先读那个函数的默认值**——我在这上面错了三次（投影/踢脚线/门套），
   还被用户当场纠正两次（窗帘/书架）。

   而 `resetMotion` 第一版正是我自己引入的回归。

   "泳池 0.39 图元/m² 是全屋最空" 比 "泳池有点空" 能直接指导动手。
